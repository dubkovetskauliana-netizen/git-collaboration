### Що я дізнався



- Різниця між `fork` і `clone`: fork створює копію репозиторію на GitHub, clone — локальну копію на комп'ютері

- Призначення `origin` та `upstream`: origin вказує на власний fork, upstream — на оригінальний репозиторій

- Створення окремої feature-гілки замість роботи напряму в `main`

- Синхронізація гілки з `upstream/main` через `git pull` та `git merge`

- Оформлення повідомлень комітів за стандартом Conventional Commits



### Враження від роботи з Git та GitHub



Модель роботи через fork і Pull Request спочатку здається складнішою за прямий push, але стає зрозумілою на практиці: кожен працює у власній копії, а зміни потрапляють в основний репозиторій лише після перевірки. Окрема гілка під кожну задачу дозволяє не боятися зламати робочий код.
